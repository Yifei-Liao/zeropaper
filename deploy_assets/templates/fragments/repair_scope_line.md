**Repair scope line.** Directly under any verdict other than PASS, write one line: `**Repair scope: release**` or `**Repair scope: analysis**`. Write `release` only when every finding in this report is discharged by rebuilding the release member alone with the analysis receipt byte-identical: each finding's locus is a file under the release directory (`output/dataset/…`), the release manifest, provenance map, or run plan, or a module the release's `build_sources` packages that the analysis receipt does not bind. A finding against the report, an analysis artifact, the renderer, a cache, or any module the analysis receipt binds is `analysis`. When in doubt write `analysis`; the orchestrator reads a missing line as `analysis`. The line names the scope of the repair, never its content — the trusted runner refuses a release re-run whose analysis receipt no longer verifies, and every auditor re-judges the rebuilt pair.
